# Airbyte 2.2

<!-- vale off -->

A Helm chart walks into a cluster. The API server asks, “Do you have a reservation?” The Helm chart says “No, but I have a release.” Airbyte version 2.2 was released on August 10, 2026.

<!-- vale on -->

:::warning Self-Managed Enterprise
**If you still use Self-Managed Enterprise, do not upgrade.** Speak to your Airbyte representative about switching to one of Airbyte's Cloud plans, which always have the latest capabilities and security improvements. Private Link is available if you require it.

## Helm chart improvements

- **Namespace override**: Both the main chart and the data plane chart accept a top-level `namespaceOverride` value, which controls the namespace written onto the resources the chart creates and used for internal service discovery. Previously these always followed the release namespace, which broke installs that render the chart into a different namespace.

- **Storage and service configuration for bundled components**: The bundled PostgreSQL and MinIO deployments and the server service accept more configuration: `postgresql.storage.volumeClaimValue` sizes the database volume, `minio.storage.storageClassName` selects a storage class for the MinIO volume, and `server.service.nodePort` sets an explicit NodePort when the server service type is `NodePort` or `LoadBalancer`. Both volume claim values apply at install time only. To grow the volume on an existing installation, expand the PersistentVolumeClaim directly.

- **Bootloader annotations**: You can annotate the bootloader with `airbyteBootloader.annotations` and `airbyteBootloader.podAnnotations`, which is useful for service meshes and job-scraping tools that need to ignore or special-case it.

- **Legacy job resource values still apply**: `global.jobs.resources` is deprecated in favor of `global.workloads.resources.mainContainer.{cpu,memory}.{request,limit}`, but it now works as a per-key fallback for the rendered `JOB_MAIN_CONTAINER_CPU_LIMIT`, `JOB_MAIN_CONTAINER_CPU_REQUEST`, `JOB_MAIN_CONTAINER_MEMORY_LIMIT`, and `JOB_MAIN_CONTAINER_MEMORY_REQUEST` values. Setting the newer values doesn't suppress the legacy ones, so remove `global.jobs.resources` once you migrate.

- **Chart renders cleanly through Kustomize**: The chart no longer emits duplicate `DATAPLANE_CLIENT_ID_SECRET_KEY` and `DATAPLANE_CLIENT_SECRET_SECRET_KEY` keys, and the Temporal UI deployment's resource and security context blocks are indented correctly. Duplicate keys and malformed indentation caused failures when piping `helm template` output into Kustomize.

- **Orchestrator resources sized separately from jobs**: `REPLICATION_ORCHESTRATOR_CPU_LIMIT`, `REPLICATION_ORCHESTRATOR_CPU_REQUEST`, `REPLICATION_ORCHESTRATOR_MEMORY_LIMIT`, and `REPLICATION_ORCHESTRATOR_MEMORY_REQUEST` are now bound explicitly, so you can size the replication orchestrator independently of your connector containers. If you don't set them, the matching `JOB_MAIN_CONTAINER_*` values still apply.

- **External database requirements documented**: If you set `global.database.type` to `external`, your PostgreSQL server must be version 13 or later. Airbyte tests through PostgreSQL 17.

- **Chart metadata for Artifact Hub**: The version 2 charts now carry license, source, documentation, and support annotations, so the chart listing links back to the right places.

## Connector & sync management

- **Syncs with no records no longer fail**: The container orchestrator treated a destination that had received no records as stale and terminated it, which failed syncs that legitimately had nothing to transfer. These syncs now complete normally.

- **Correct CPU parsing when sizing sockets**: The workload launcher misread Kubernetes CPU limits expressed in millicores, such as `500m`, when calculating how many sockets to allocate for a sync. These limits are now parsed correctly, so connector concurrency matches the resources you configured.

- **Refreshed OAuth credentials persist immediately**: When a connector emits a `CONTROL` message with updated OAuth configuration, Airbyte persists it as soon as it arrives instead of at the end of the sync. A later failure in the same sync no longer discards the refreshed credentials.

- **Failed OAuth handshakes leave nothing behind**: A source OAuth completion that fails no longer writes a secret, so your secrets backend doesn't accumulate unusable entries.

- **Orphaned secrets are deleted as they're created**: Airbyte-managed secrets that become orphaned when you update or delete a source or destination are now deleted inline, rather than waiting for the cleanup cron.

- **Recovery window for AWS Secrets Manager deletions**: Orphaned-secret cleanup now requests a seven-day recovery window when deleting from AWS Secrets Manager, so an unintended deletion can be restored.

- **Secret storage configuration is validated up front**: Airbyte checks that an AWS, Azure, GCP, Vault, or runtime secret storage configuration has the fields its backend requires when you create it, instead of failing later when a sync tries to read a secret.

- **Amazon Seller Partner supports the Ireland region**: OAuth consent URLs are now generated for the `IE` region, so Irish sellers can authenticate.

- **Shopify OAuth errors are readable**: A failed Shopify token exchange now reports the HTTP status and the error Shopify returned instead of a generic failure.

- **Custom sources report file transfer support correctly**: For custom declarative sources, `supportsFileTransfer` is derived from the connector manifest, so file-based streams are available without republishing the connector.

## New features

- **Warning before a large first sync**: When you create a connection whose selected streams imply a very large initial sync, Airbyte now warns you in the connection creation flow before you start it.

## Security improvements

- **Client-supplied authentication headers are stripped**: Internal authentication headers sent by a client are removed before the server derives trusted identity headers from the request, closing a path to cross-tenant authorization.

- **Stronger password policy in the bundled Keycloak**: The bundled Keycloak image ships a much larger blacklist of common and breached passwords, which it rejects when users set or change a password.

- **SSO client secrets masked in audit entries**: Audit entries for SSO configuration changes no longer record the `clientSecret` value.

- **Invitation codes no longer exposed**: Administrative invitation reads and cancellations reference invitations by ID and return an admin-safe payload, so invite codes aren't disclosed.

## Bug fixes

- **Rejected client credentials return 401**: Application credentials that Keycloak rejects now produce a `401 Unauthorized` response instead of a `500`.

- **No browser credential prompt on community deployments**: Unauthenticated requests to a community-edition deployment no longer advertise an HTTP Basic authentication challenge, which caused browsers to pop up a native username and password dialog.

- **Connection pages load when schema discovery fails**: A failed schema discovery no longer produces a `500` when loading a connection, so you can reach the connection and fix the underlying problem.

- **Workspace admins can read their organization**: Workspace administrators can call `/v1/organizations/get` for the organization that contains their workspace.

- **Jobs that never start are marked failed**: A queued job that can't begin execution can now transition directly to `FAILED` instead of remaining queued.

- **Duplicate attempt creation returns a conflict**: Creating an attempt for a job that's already running or already finished returns `409 Conflict` instead of producing an ambiguous second attempt.

- **Connector Builder stream testing isn't blocked by other streams**: The stream test button only validates the stream you're testing, instead of also reporting errors from unrelated streams.

- **Network policy labels use the configured cache name**: Workload NetworkPolicy labels are generated from the configured cache name rather than a default one.

- **Faster job history queries on large installations**: Job pruning runs with a ten-minute statement timeout, attempt statistics are fetched in batches instead of one large join, and new indexes on `jobs(created_at)` and the commands workload lookup are added by migration. Installations with long job histories should see faster job list and cleanup operations.
