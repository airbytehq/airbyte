# Airbyte 2.6

<!-- vale off -->

Airbyte version 2.6 was released on November 25, 2026. This version includes security fixes in Airbyte's dependencies and across the platform, including the Java4Shell (CVE-2026-114938) vulnerability. Upgrade promptly.

<!-- vale on -->

:::warning Airbyte 2.5 users: upgrade immediately
If you deployed version 2.5 of Airbyte on November 25, 2026, rotate your environment variables, and upgrade to this version immediately due to the possibility that your version 2.5 platform images could be compromised. Version 2.5 is considered safe if installed before or after the affected window of time, but we still recommend running this version of Airbyte, which includes many more security improvements. For full details, see [Security advisory for open-source users: Java4Shell fix & compromised images](https://airbyte.com/blog/advisory-for-open-source).
:::

## Before you upgrade

- **Raw webhook operations removed**: Webhook operations now only run dbt Cloud jobs. Operations you saved earlier in the raw form stay in the database but fail when they run. Airbyte now sends webhook requests only to dbt Cloud job run URLs on `getdbt.com` and `dbt.com` hosts. Before you upgrade, re-create any raw webhook operations as dbt Cloud jobs, and move any dbt Cloud host outside `getdbt.com` and `dbt.com`.

- **Local data plane moves to the `AUTO` group**: On upgrade, Airbyte moves the existing local data plane into the `AUTO` data plane group and restarts the workload launcher so it polls the repaired group. This fixes jobs that were stuck in `Queued` on deployments whose data plane belonged to an unnamed group. Expect the launcher to restart during the upgrade.

## Helm chart improvements

- **Dedicated service account for the manifest server**: The manifest server no longer shares the chart's main service account. The chart now creates a dedicated `<release>-manifest-server` service account, and the pod no longer mounts a Kubernetes API token. To run the manifest server in the jobs namespace instead, where its network policies cover outbound calls, set `manifestServer.runInJobsNamespace: true`.
- **Manifest server 7.28.2 to 7.50.1**: The Connector Builder's manifest server image moves from 7.28.2 to 7.50.1, bringing it current with upstream fixes.
- **New direct job runner options**: The runner's connector jar cache is now configurable with `directJobRunner.jarCache.mountPath` (default `/tmp/airbyte-connector-jars`) and `directJobRunner.jarCache.sizeLimit` (default `5Gi`, also the pod's ephemeral-storage request). Two new values, `directJobRunner.manifestServerSecretName` and `directJobRunner.featureFlagsSecretName`, hold secrets the runner needs in the jobs namespace. `autoscaling` defaults now run 2 to 5 replicas instead of 4 to 10.
- **`dataPlane.id` on the data-plane chart**: The `airbyte-data-plane` chart accepts an optional `dataPlane.id` UUID, used for data plane authentication diagnostics. The default is now empty instead of `local`, so an existing install sends nothing until you set the value. The chart also removes the unused `dataPlane.serviceAccountEmail` and `dataPlane.serviceAccountCredentialsPath` values and no longer mounts the unused data plane service account key on launcher, runner, and job pods.
- **Dead environment variables removed**: Job pods no longer receive `S3_PATH_STYLE_ACCESS`, `DATA_PLANE_SERVICE_ACCOUNT_EMAIL`, or `DATA_PLANE_SERVICE_ACCOUNT_CREDENTIALS_PATH`, none of which any code read. This also removes the `Unsetting empty environment variable` messages from pod startup logs.

## Bug fixes

- **Duplicate jobs no longer freeze connections**: When Temporal retries a slow job creation, Airbyte now returns the active job instead of failing it and creating a second job that stays pending forever. Connections that froze before the upgrade stay frozen; recover them by cleaning up the pending job and starting a sync manually.
- **Configured labels reach workload pods**: Labels you set with `global.jobs.kube.labels` (`JOB_KUBE_LABELS`) now apply to sync, check, discover, and spec pods. Before, the launcher received them but never put them on the pods.
- **Digest-pinned images work in pod labels**: An image reference like `image:tag@sha256:<digest>` no longer produces an invalid 64-character pod label, which caused pod creation to fail. Labels now use the tag, and the full digest-pinned reference still goes to the container image.
- **JVM heap defaults restored**: Container orchestrators and workload init containers (check, discover, and spec) now default to `-XX:MaxRAMPercentage=75.0`, and the orchestrator also gets `-XX:+ExitOnOutOfMemoryError`. Without explicit defaults they could fall back to the JVM default of 25% of heap. Custom `CONTAINER_ORCHESTRATOR_JAVA_OPTS` values still take precedence.
- **Organization creation requires an email**: The Config API now validates `email` up front when creating an organization instead of failing with an HTTP 500.
- **`X-Airbyte-*` headers no longer trusted**: Audit and telemetry IDs now come from parsed request values instead of client-supplied `X-Airbyte-*` headers. Integrations that set those headers see them ignored; authentication is unaffected.
- **Failed connection tests stay visible**: A failed connection test now shows in a panel over the setup form's footer buttons instead of a toast and a card that could render below the fold.
- **Sync log storage gets a periodic write check**: The workload launcher now verifies every 30 minutes that the data plane can write to its sync log storage, creating a small `storage-check-*` file in the log bucket on each run. You may notice these test files in your log storage.

## Connector Builder improvements

- **Publishing is atomic**: Publishing a Connector Builder project now happens in one transaction. Duplicate or concurrent publish requests get a 409 error instead of potentially leaving orphaned connector definitions.
- **Consent URLs must use HTTPS**: Connector Builder OAuth consent URLs must now be `https://` URLs with a valid host.

## Security improvements

- **Base Java image updated**: `airbyte-base-java-image` 3.3.19 moves the JDK to Corretto 21.0.13.1, which fixes Java4Shell (CVE-2026-114938), and fixes 14 High and Critical vulnerabilities in OS packages found in routine image scanning.
- **Platform hardening**: This release includes a set of security fixes informed by additional external penetration testing. For security reasons, expect no further commentary.
